# Ether v0.3.7

Hotfix for two upgrade issues reported on `v0.3.6`.

## Quality profiles and client rules

- **Client rules naming removed quality profiles are repaired automatically on startup.** Upgrading from `0.3.5` (or restarting a server already on `0.3.6`) resets pre-standard quality profiles to the shipped defaults while keeping client rules. Rules that pointed to a custom or TRaSH/Profilarr-imported profile now repoint to your At home default profile for that media while keeping their device/viewer matchers, resolution limits and surround-audio settings intact, instead of blocking settings saves and profile imports with `quality.rules[…].profile names a profile that does not exist`. Applies to both single-server `config.json` and shared PostgreSQL cluster settings.
- **Unrelated broken rules no longer trap quality or rule edits in the console.** Saving or removing a quality profile or client rule in **Releases › Quality profiles** or **Releases › Client rules** also settles any other rules whose profile no longer exists.

## Remote access and shared users

- **Post-upgrade SQLite maintenance no longer trips `database is locked` across background workers or `Shared users are not syncing` (#407).** On large libraries upgrading to `0.3.6`, background popularity-rank and title-index builds, full planner-statistics scans and post-migration `PRAGMA wal_checkpoint(TRUNCATE)` could hold SQLite past 10 seconds, failing availability publication, show-date refresh and `plex.tv` friend sync and leaving **Remote access — Shared users are not syncing** on the dashboard for up to 30 minutes. Index and statistics builds (plus `DROP`/`ALTER` DDL) now queue in-process writers cleanly through the write gate, the startup WAL checkpoint completes before background workers launch, transient write contention retries friend sync in 15 seconds without raising a false health warning, and other transient friend-sync errors back off from 1 minute instead of waiting 30 minutes.
- **Manual shared-user sync and clearer connectivity & catalogue status (#407).** **Viewers** and **Apps › Plex › Remote access** now include a **Sync shared users** action alongside last-sync status (and **Run checks again** also re-runs shared-user sync), `plex.tv` registration waits until the HTTP/TLS listener and library sections are ready before starting inbound connectivity checks, `plex.tv connectivity check` logs record `direction=inbound` with the probed `address` and `port`, remote stream/session grants keep external client reachability fresh during long plays, and catalogue sync status keeps your library title count visible (`48,438 titles · syncing (113,420 checked)`) instead of replacing it with scanned TMDB row counts.

## Upgrading

- **No manual steps required.** Upgrade to `0.3.7` and start Ether; affected servers repair `config.json` (and shared cluster settings) automatically on startup. Once upgraded, recreate or re-import any custom profiles and select them on your client rules if desired.
- If you are upgrading directly from `0.3.5` or earlier, all upgrade guidance in the [v0.3.6 release notes](https://github.com/braedonsaunders/ether/releases/tag/v0.3.6) still applies.
